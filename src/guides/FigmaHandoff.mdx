# Figma Handoff

Nexa connects design intent to a tested React implementation:

**Figma variables/styles → component instances → Dev Mode inspection → Nexa React APIs → Storybook → implementation verification.**

**Current status:** React components, themes, stories and tests exist. A [Figma design reference](https://www.figma.com/design/dOGqmnvbpkcCjZDKagTMVH) is now supplied. Metadata confirms Cover and Foundations frames; complete component bindings, Dev Mode comparison and designer sign-off remain unverified. This guide does not represent a completed Figma integration.

Focus and hover are browser states, not new props. MUI keeps keyboard, focus and input behavior; consumers own values and actions. Use controls and the Theme toolbar to inspect the existing contract before proposing a new variant.

## Tokens have meaning, not just values

- Bind primary actions to color/primary/main → palette.primary.main. The palette maps different primitive shades in Light and Dark modes.
- Figma gap 16px → theme.spacing(4). Figma radius 8px → sx borderRadius: 1.
- Use text styles for composite typography. Record the actual font used for comparison; CSS uses a system fallback stack.
- Primitive shadow tokens currently do not replace MUI elevations. Do not treat their existence as evidence that every component uses them.

The TypeScript tokens and MUI adapter are authoritative for implemented values. No separate manually maintained JSON token source is introduced.

## Designer and developer workflow

1. Create instances from the future Nexa Figma library and bind approved variables/styles.
2. Supply responsive constraints, states, interaction notes and accessibility intent.
3. In Dev Mode, inspect the real component, variant, bindings and version; match it to the Nexa API.
4. Implement with theme values and existing compositions. Interpret generated CSS rather than copying it blindly.
5. Compare matching viewports, themes, fonts and data; test keyboard behavior and accessibility.
6. Review differences with designer/QA and record acceptance evidence.

Storybook is the **coded source of truth for demonstrated component behavior**, not proof of Figma parity. Its stories, controls and tests make the contract reviewable. Approved design changes must update both design and implementation references.

## Trace a real composition

The <a href="./?path=/docs/patterns-enterprise-learning-administration--docs" target="_top">Learning Administration pattern</a> combines shell, navigation, breadcrumbs, metrics, grid, status badges and a date filter. The grid scrolls internally on narrow screens; navigation changes to a modal drawer below 1200px. Metrics are illustrative and separate from the 24 sample records.

Unit/browser tests cover specific interactions. Screen-reader acceptance, Figma visual comparison and designer approval remain manual tasks.
