Status: proposed Figma component sets mapped to existing React APIs. No actual Figma node IDs or Code Connect mappings exist. Source APIs and Storybook are the implemented contract. Import public components from src/index.ts; keep application data and events in the consumer.

Figma property labels use readable names; React props use their existing spelling. Theme is a variable mode, not a duplicated variant on every component. Hover, focus, and pressed states are design specifications for MUI/CSS behavior, not invented React state props.

## Worked property translation

Figma Button: Variant=Primary, Size=Medium, State=Default, Label=Save changes.

```tsx
<NexaButton variant="primary" size="medium" onClick={saveChanges}>
  Save changes
</NexaButton>
```

For State=Loading, set loading from the request state; do not replace the button with an unrelated spinner. For State=Focus, use keyboard focus in Storybook; do not add a focus prop. Do not use an action button as a navigation link: NexaButton intentionally omits href/component.

Figma Status Badge: Status=Success, Label=Completed maps to:

```tsx
<NexaStatusBadge status="success" label="Completed" />
```

In the enterprise example, In progress maps to info, Overdue to error, and Not started to neutral. This is a consuming-domain mapping in enterpriseData.tsx, not a universal rule that every overdue status must be red.

## State coverage and limits

Design default, hover, focus-visible, pressed where relevant, disabled, error/helper, loading, and selected states. Use boolean/text/instance-swap properties for content instead of generating a variant for every label/icon combination. Responsive shell layouts and theme modes are contextual behavior. MUI owns grid cell navigation, menu focus, dialog trapping, and date sections; annotations must preserve those behaviors.

Use [Storybook component docs](http://localhost:6006/?path=/docs/components-button--docs) and the [traceability matrix](implementation-traceability.md). New appearances without a current prop should be logged as a design-system proposal, not implemented with one-off CSS or misrepresented as supported variants.
